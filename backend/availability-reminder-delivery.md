# Воскресное напоминание о слотах · B-07

Расписание: воскресенье **18:00 МСК**, expiry **21:00 МСК** того же дня. Адресуемая неделя — следующий календарный понедельник, не относительный индекс в текущем интерфейсе. Время берётся из PostgreSQL `clock_timestamp()`, не из часов JVM или устройства пользователя.

`AvailabilityReminderPlanner` вызывается существующим sender вместе с task/meeting planners. V025 хранит один occurrence на week_start и неизменные targets. PostgreSQL unique key, occurrence, targets и delivery links в одной транзакции исключают дубли при повторном запуске и двух workers. Новая очередь, отдельный таймер, Redis и зависимости не добавлены. Один недельный снимок создаётся в одной транзакции; для существенно большей команды потребуется поэтапная материализация **после** сохранения полного снимка, не чтение новой аудитории частями.

В снимок входят только активные зарегистрированные admin/organizer, не заполнившие следующую неделю. Faculty-роли исключены согласно правам API слотов. Используется общий `AvailabilitySubmissionService.submitted`: «вне недели» означает заполнено; иначе нужны ответы для всех текущих activeDays, а available-день требует хотя бы один слот. Смена activeDays учитывается при проверке перед отправкой. Пользователь без положительного Telegram ID сохраняется как unavailable, а не sent. Новые участники, очищенные после снимка ответы и новые Telegram-привязки существующее намерение не расширяют.

Queue start повторно проверяет состояние occurrence/target, due/expiry, текущие роль/активность/регистрацию, неизменный личный chat ID и заполненность конкретной недели. Группы и топики не создаются. `disable_notification=false` сохранён из прежнего Sunday-потока. Текст сохранён; кнопка открытия Mini App относится к Telegram-интеграции B-08, транспорт этого блока пока передаёт только текст.

Проверка «не раньше due» остаётся в общей финальной queue-проверке, а domain gate проверяет совпадение delivery intended_at с occurrence. Если часы БД отступили после claim, преждевременная попытка не начинается и намерение не отменяется: после корректировки времени/lease recovery оно остаётся доступным внутри grace.

После restart внутри grace отправка остаётся привязана к исходным 18:00, не ко времени запуска. После grace сохраняется expired occurrence без рассылки; пропущенные старые недели не проигрываются пачкой. Planner рассматривает только последний календарный Sunday, до 18:00 текущего воскресенья ничего не создаёт. Старые недоставленные deliveries закрывает штатный queue expiry. Sent/unknown не переиздаются: expired lease до HTTP может быть восстановлен, после start становится unknown. Retry/429, quota и журнал попыток общие; UI/ручной retry этого системного события пока не добавлены.

Изолированные integration tests используют отдельную Testcontainers PostgreSQL и тестовую подмену SQL clock в **своём** schema/search_path. Проверки не меняют часы ОС или БД live-test/production; подмена удаляется после каждого теста. Все отправки — fake transport.
