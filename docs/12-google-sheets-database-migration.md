# Хранилище MegaBot в Google Sheets

Для базы используется отдельная Google-таблица. Таблица доступности с листом `ОСНОВА` остаётся пользовательским интерфейсом расписания и не смешивается с внутренним хранилищем.

## Доступ и секреты

Таблицу нужно открыть сервисному аккаунту MegaBot с ролью «Редактор». Публичный доступ для работы бота не требуется и после проверки может быть отключён. JSON-ключ сервисного аккаунта хранится только на Selectel; в Git его добавлять нельзя.

Переменные окружения:

```env
GOOGLE_SERVICE_ACCOUNT_FILE=/opt/megabot/service-account.json
GOOGLE_SHEETS_DATABASE_SPREADSHEET_ID=1R1MtYJfEuGNw0JI_laNmRk_Un7wIQwxt0xRYTp3mih4
GOOGLE_SHEETS_DATABASE_ENABLED=false
```

## Структура

Инициализатор сам создаёт и оформляет 16 листов:

- `meta` — версия схемы, ревизия и состояние снимка;
- `snapshot` — полный JSON-снимок, разбитый на безопасные фрагменты для точного восстановления всех полей;
- `events`, `users`, `faculties`;
- `availability_weeks`, `availability_slots`;
- `meetings`, `meeting_participants`;
- `tasks`, `task_assignees`, `task_comments`, `task_reminders`;
- `bot_messages`, `settings`;
- `audit_log` — журнал выгрузок.

Связи хранят стабильные ID. Задачи разных мероприятий разделяет `event_id`; отдельный лист на каждое мероприятие не создаётся.

## Безопасное включение

Сначала оставить `GOOGLE_SHEETS_DATABASE_ENABLED=false`, затем выполнить:

```bash
npm run db:sheets:check
npm run db:sheets:migrate
npm run db:sheets:verify
```

`check` подтверждает именно право записи и создаёт структуру. `migrate` перед изменениями создаёт рядом с `database.json` файл `database.backup-before-google-sheets-<timestamp>.json`, переносит данные, читает их обратно, сверяет связанные сущности и SHA-256 полного снимка. Только после успешного результата можно поставить `GOOGLE_SHEETS_DATABASE_ENABLED=true` и перезапустить бота.

## Работа и восстановление

При включённом режиме Google Sheets является долговременным источником данных, а `database.json` остаётся атомарно обновляемым локальным кэшем и аварийной копией. Записи объединяются в очередь: бот не ждёт сеть при каждом пользовательском действии, но отправляет последний полный согласованный снимок.

Перед обновлением листов снимок получает состояние `writing`, после успешной записи — `ready`. Незавершённый снимок никогда не загружается как база. Если Google временно недоступен, бот продолжает работать из JSON и повторяет синхронизацию. При старте сравниваются ревизии: более новый согласованный снимок Google загружается локально, а более новый JSON восстанавливает Google Sheets.

Проверка состояния:

```bash
npm run db:sheets:status
curl -fsS http://127.0.0.1:3000/api/health
```
