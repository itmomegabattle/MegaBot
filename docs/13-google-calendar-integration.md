# Интеграция Google Calendar

## Назначение

MegaBot выгружает все собрания в командный Google Calendar. База MegaBot остаётся источником истины: календарь предназначен для общего просмотра, а ручные изменения событий обратно в бота не импортируются.

Целевой календарь:

```text
b8ce7f1ecee245cd75d151392661008b9bd79fe498ee412692ad7ac9848b91e0@group.calendar.google.com
```

## Доступ

1. В проекте Google Cloud сервисного аккаунта включить Google Calendar API.
2. В настройках целевого календаря открыть раздел доступа для отдельных пользователей.
3. Добавить `tg-megabot-sheets@tg-megabot.iam.gserviceaccount.com`.
4. Выдать право `Вносить изменения в мероприятия` / `Make changes to events`. Публичный доступ календарю не нужен.

Используется существующий закрытый JSON-ключ из `GOOGLE_SERVICE_ACCOUNT_FILE`; новый ключ создавать не требуется.

## Переменные Selectel

```env
GOOGLE_CALENDAR_ID=b8ce7f1ecee245cd75d151392661008b9bd79fe498ee412692ad7ac9848b91e0@group.calendar.google.com
GOOGLE_CALENDAR_ENABLED=true
GOOGLE_CALENDAR_TIME_ZONE=Europe/Moscow
```

Проверка доступа:

```bash
npm run calendar:check
```

Первичная идемпотентная синхронизация существующих собраний:

```bash
npm run calendar:sync
```

## Состав события

- название собрания записывается в заголовок;
- дата и время используются в часовом поясе `Europe/Moscow`;
- длительность берётся из собрания, а при отсутствии или некорректном значении используется один час;
- в описание записываются описание, повестка, направление, формат, организатор, участники, подтвердившие участие и внутренний ID MegaBot;
- изменение собрания обновляет то же событие;
- отмена собрания удаляет событие;
- повторный запуск безопасен и не создаёт дубликаты.

Если Google временно недоступен, собрание всё равно сохраняется в MegaBot. Сервер ставит его в очередь повтора, а после перезапуска сверяет календарь со всеми собраниями базы.

## Граница изменений 2026-08-09

Текущий релиз меняет навигацию, слоты и профиль, но не контракт Google Calendar. Отмена редактирования слотов не создаёт календарных операций. Будущие режимы назначения задач также не должны попадать в Calendar API без отдельного продуктового решения о task deadlines как событиях.
