# Интеграция Google Sheets

## Принятые правила

- единственный рабочий лист доступности: `ОСНОВА` (`sheetId: 1910422522`); переименование не ломает интеграцию, потому что главным идентификатором остаётся `sheetId`;
- пользователь связывается со строкой через Telegram ID, первичное сопоставление выполняется по нормализованному ФИО;
- номер строки не сохраняется: строки перечитываются, поэтому сортировка, добавление и удаление людей не сдвигают чужие данные;
- при конфликте побеждает последнее подтверждённое изменение;
- граница недели: понедельник, 00:00, `Europe/Moscow`;
- истёкшие недели удаляются из оперативной доступности без архива;
- Mini App может показывать от двух до пяти недель, но Google Sheets всегда синхронизирует только текущую неделю на листе `ОСНОВА`;
- при смене недели или настроек сервер сначала создаёт полную резервную копию `ОСНОВА`, затем перестраивает даты и часовые колонки по активным дням/часам из админки и восстанавливает checkbox-валидацию;
- отдельные листы `Неделя YYYY-MM-DD` больше не создаются; уже созданные листы скрываются без удаления данных;
- Apps Script отправляет изменения таблицы сразу, сервер дополнительно сверяется с таблицей каждые 15 секунд; открытие Mini App запускает сверку с трёхсекундным TTL.

## Секреты на Selectel

Ключ service account не хранится в Git и не должен лежать в рабочем дереве `/opt/megabot` под отслеживаемым именем.

С локального компьютера:

```bash
scp /local/path/google-key.json root@139.100.235.189:/tmp/megabot-google-key.json
```

На сервере:

```bash
cd /opt/megabot
sudo bash scripts/install-google-sheets-secret.sh /tmp/megabot-google-key.json
rm /tmp/megabot-google-key.json
openssl rand -hex 32
```

Последняя команда создаёт секрет для подписи webhook. Его нужно сохранить и в `.env`, и в свойствах Apps Script.

Добавить в `/opt/megabot/.env`:

```env
GOOGLE_SHEETS_SPREADSHEET_ID=16sbBKwmrUm2b6n7nZG2UYyjBk-8IkUaGJqEd-nQwtWo
GOOGLE_SERVICE_ACCOUNT_FILE=/opt/megabot/secrets/google-service-account.json
GOOGLE_SHEETS_WEBHOOK_SECRET=длинная_случайная_строка_из_openssl
GOOGLE_SHEETS_PRIMARY_SHEET_TITLE=ОСНОВА
GOOGLE_SHEETS_PRIMARY_SHEET_ID=1910422522
GOOGLE_SHEETS_TEMPLATE_SHEET_TITLE=ШАБЛОН НЕДЕЛИ
GOOGLE_SHEETS_SCAN_RANGE=A1:ZZ200
```

`GOOGLE_SHEETS_PRIMARY_SHEET_ID` является основной привязкой. Поэтому лист можно переименовать без поломки синхронизации.

Проверить права:

```bash
stat -c '%a %U:%G %n' /opt/megabot/secrets/google-service-account.json
```

Ожидаемые права: `600`. После `git pull` файл останется на сервере, потому что Git его не отслеживает.

## Установка Apps Script

1. Открыть таблицу.
2. Выбрать `Расширения` → `Apps Script`.
3. Скопировать содержимое `scripts/google-sheets-apps-script.gs` в `Code.gs`.
4. Сохранить проект.
5. Запустить функцию `setMegaBotWebhookSecret` и вставить значение `GOOGLE_SHEETS_WEBHOOK_SECRET`.
6. Запустить `installMegaBotTrigger`.
7. Подтвердить разрешения Google.
8. В разделе `Триггеры` должен появиться устанавливаемый триггер `sendMegaBotEdit` с событием `При изменении`.

Простой `onEdit` намеренно не используется: устанавливаемому триггеру разрешён `UrlFetchApp`, необходимый для HTTPS-запроса к серверу.

## Пустой шаблон

Административный endpoint `POST /api/integrations/google-sheets/template` копирует основной лист целиком и создаёт лист `ШАБЛОН НЕДЕЛИ`. Затем очищаются только ячейки временных слотов сопоставленных участников; размеры, цвета, границы, объединения, формулы и остальное оформление сохраняются.

Endpoint идемпотентен: если шаблон уже существует, второй лист не создаётся.

Шаблон не является рабочим листом и не участвует в импорте/экспорте. Все пользовательские изменения читаются и записываются только в `ОСНОВА`.

## Резервная копия и подготовка текущей недели

Перед ручным изменением рабочего листа:

```bash
npm run sheets:backup
```

Команда атомарно заменяет единственную резервную вкладку `РЕЗЕРВ ОСНОВА`, поэтому старые копии не накапливаются.

Безопасная подготовка `ОСНОВА`:

```bash
npm run sheets:prepare
```

Если даты, активные дни и часы уже совпадают с настройками, команда не очищает значения и не создаёт повторную копию: она только проверяет checkbox-валидацию и служебные привязки. При изменении недели или диапазона резервная копия создаётся до первой мутации; совпадающие дата/час сохраняют прежнее значение.

Для первого перехода со старых недельных вкладок используется единая команда:

```bash
npm run sheets:migrate
```

Она всегда создаёт и проверяет ровно одну резервную копию `ОСНОВА`, после чего использует её как защитную копию ротации и скрывает старые вкладки `Неделя …` без удаления.

## Сопоставление людей

Администратор может получить отчёт:

```text
GET /api/integrations/google-sheets/mapping
```

Отчёт содержит строку таблицы, имя в таблице, имя в приложении и Telegram ID. В автоматическое сопоставление попадают только точные совпадения после безопасной нормализации: регистр, `ё/е`, порядок имени и фамилии, лишние пробелы и знаки препинания не влияют.

Неоднозначные и отсутствующие совпадения не записываются автоматически.

## Проверка после деплоя

```bash
cd /opt/megabot
npm install
npm run build
pm2 restart megabot --update-env
pm2 logs megabot --lines 100
curl http://127.0.0.1:3000/api/health
```

В `/api/health` должно быть:

```json
"googleSheetsConfigured": true
```

После этого изменить один слот тестового администратора в таблице, открыть Mini App и проверить изменение. Затем изменить слот в Mini App и убедиться, что чекбокс таблицы обновился.

В ячейках доступности должны отображаться чекбоксы, а не текст `TRUE`/`FALSE`. `npm run sheets:prepare` повторно устанавливает Google Sheets data validation типа `BOOLEAN` и нормализует значения в настоящие boolean.

## Надёжность синхронизации — 2026-08-03

Сохранение из Mini App по-прежнему ожидает прямой экспорт и возвращает его статус API. Сохранение из Telegram-чата сначала фиксирует данные локально и добавляет пользователя в `pendingSheetExports`. Фоновый flush отправляет последнюю доступность и удаляет запись только после успеха.

Fallback reconciliation запускается раз в 15 секунд. Порядок принципиален: сначала повторяются ожидающие экспорты приложения, затем импортируются изменения таблицы. Apps Script остаётся быстрым push-каналом таблица → сервер, а периодический импорт — страховкой. Импорт `ОСНОВА` заменяет только текущую неделю и не стирает независимо сохранённые будущие недели.

После деплоя обязательны:

```bash
npm run sheets:mapping
npm run sheets:roundtrip-test
```

Следующие улучшения: сохранять время/ошибку каждой попытки, показывать очередь в админской панели, добавить exponential backoff и dead-letter состояние, а также использовать версию изменения для формального разрешения гонок «последнее подтверждённое изменение побеждает».

## Актуализация 2026-08-09

`ОСНОВА` содержит две последовательные недели в одном рабочем листе и остаётся единственной пользовательской точкой редактирования. Конфигурация дней и часов определяет обе секции; бот и таблица импортируют и экспортируют одинаковые диапазоны. Day-level `Отменить` в Telegram работает только с локальным черновиком и не запускает экспорт, пока пользователь не нажал `Сохранить`.

Повторяющаяся ошибка — считать внешний вид листа схемой данных. Перед изменением диапазонов сначала проверять layout обеих недель, затем mapping, export/import preview и round-trip на Selectel; резервную вкладку не использовать как рабочий источник.
